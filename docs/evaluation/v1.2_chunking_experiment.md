## 1. Executive Summary

In accordance with `docs/Product-Roadmap.md` and `docs/Research-Roadmap.md`, an isolated, evaluation-only chunking experiment was conducted against the frozen 50-document expanded corpus and 80-case benchmark.

The experiment evaluated whether replacing whole-document / fixed-window chunking (`FixedSizeChunker(chunk_size=1000, overlap=200)`) with a deterministic sentence-boundary chunker (`SentenceBoundaryChunker(target_chunk_size=400, min_chunk_size=150, overlap_sentences=1)`) improves retrieval quality—specifically targeting boundary handling and exact terminology—while maintaining system latency within guardrails.

### Key Conclusions

1. **Successful Domain-Specific Gains:**  
   Sentence boundary chunking substantially improved retrieval on fine-grained, localized information:
   - `boundary_handling` MRR rose sharply from **0.5250 to 0.6917** (+0.1667, passing the $\ge 0.6500$ secondary target).
   - `exact_terminology` Hit@1 reached **0.8125** (up from 0.6875, passing the $\ge 0.7500$ secondary target).
   - Top-5 document recall (`Hit@5`) expanded from **0.8750 to 0.9125** when document-level deduplication was enabled.
2. **Context Fragmentation Dilutes Semantic Thematic Queries:**  
   In the baseline, documents averaged 812.6 characters, meaning fixed 1000-character chunks captured the entire document context in a single embedding. Splitting documents into ~400-character chunks fragmented broader thematic narrative, causing significant regressions in:
   - `paraphrase` MRR dropped from **0.9375 to 0.8125** (-0.1250).
   - `hard_negative` MRR degraded from **0.4427 to 0.3563** (-0.0865).
   - `multi_concept` MRR suffered a safety violation (**1.0000 to 0.9688**), failing query `exp-038` where cosine metric conversion was separated from higher-level vector provider context.
3. **Document-Level Deduplication is Mandatory for Sub-Document Chunking:**  
   When top-K retrieval was evaluated purely on raw chunks, overall MRR dropped to **0.7300** and Hit@3 fell to **0.8000** because multiple sibling chunks from the same non-relevant distractor document occupied candidate slots. Applying document-level deduplication recovered MRR to **0.7471** and raised Hit@5 to **0.9125**.
4. **Latency Profile Remained Well Within Budget:**  
   Query retrieval latency was unaffected by the increased index size (P95 of 618.6 ms vs control 643.0 ms), as HNSW vector search scales logarithmically.

**Decision:** The treatment is **REJECTED** as a standalone retrieval replacement. While sentence segmentation successfully solves boundary fragmentation, standalone fine chunking causes net regression in semantic thematic retrieval.

## 2. Hypothesis

**Hypothesis:**  
Replacing arbitrary character-count document splitting with natural sentence boundary segmentation (`target_chunk_size=400`, `min_chunk_size=150`, `overlap_sentences=1`) will eliminate cross-sentence semantic truncation at chunk boundaries, raising exact terminology and boundary handling retrieval accuracy and lifting overall MRR from 0.7623 to $\ge 0.8200$ without violating the P95 query latency budget ($\le +100$ ms).

**Tested Assumptions:**
1. Ground-truth information in technical documents aligns with coherent multi-sentence blocks rather than arbitrary 1000-character boundaries.
2. Sentence-bounded chunks provide higher semantic density for exact architectural queries.
3. Sub-document chunking does not dilute query-document relevance for multi-concept or paraphrase queries.

## 4. Deterministic Chunking Specification & Edge Cases

The implementation [`SentenceBoundaryChunker`](../../backend/app/services/chunking/chunkers/sentence_boundary.py) satisfies strict deterministic rules:

### 4.1 Boundary Splitting Rules
- **Regex Split Pattern:** `(?<=[.!?])\s+(?=[A-Z0-9"'\(\[])` splits text on punctuation followed by whitespace and a capital letter, number, or quote.
- **Abbreviation Protection:** Common abbreviations (e.g., `e.g.`, `i.e.`, `vs.`, `Fig.`, `et al.`) are preserved to prevent mid-clause splitting.
- **Target Size & Sentence Accumulation:** Sentences are accumulated into a chunk until adding another sentence exceeds `target_chunk_size` (400 characters).
- **Sentence Overlap:** When rolling over to the next chunk, `overlap_sentences` (1 sentence) from the tail of the previous chunk is prepended, unless that sentence alone exceeds `target_chunk_size`.

### 4.2 Edge Case Rules
1. **Oversized Sentences:**  
   If a single sentence exceeds `target_chunk_size`, it is sliced deterministically into sub-chunks of length `target_chunk_size`, preserving character indices and ordering.
2. **Short Trailing Fragments:**  
   If the final accumulated sentence group has length `< min_chunk_size` (150 characters) and there is a preceding chunk, it is appended to the preceding chunk rather than discarded or left as an orphan.
3. **Text Without Punctuation:**  
   If the document contains no sentence delimiters, the sentence detector yields a single block which is sliced deterministically at `target_chunk_size` boundaries.
4. **Document Boundary Overlap:**  
   Overlap is strictly intra-document. Chunks from Document $A$ never share overlap or state with Document $B$.

- `exp-068` [cross_document]: MRR **0.50 $\rightarrow$ 1.00** (+0.50).

### 9.2 Key Regressions (-13 cases)
1. **Thematic / Semantic Cohesion Dilution (`paraphrase`):**

     *Root Cause:* In control, the entire document was present in one chunk, binding environment variables, seeds, and path normalization together. In treatment, the seed configuration chunk lacked the cross-platform path explanation, pushing the relevant chunk down to rank 4.
   - `exp-029` [paraphrase]: MRR **1.00 $\rightarrow$ 0.25** (-0.75).  
     *Query:* "What prevents random web crawlers from injecting malicious feedback rows into Google Sheets?"  
     *Root Cause:* The security paragraph separated the authentication token check from the Sheets API append call.
   - `exp-018` [paraphrase]: MRR **1.00 $\rightarrow$ 0.50** (-0.50).
   - `exp-024` [paraphrase]: MRR **1.00 $\rightarrow$ 0.50** (-0.50).
2. **Safety Target Regression (`multi_concept`):**
   - `exp-038` [multi_concept]: MRR **1.00 $\rightarrow$ 0.50** (-0.50).  
     *Query:* "How does QdrantVectorStoreProvider map cosine distance metrics into similarity scores?"  
     *Root Cause:* The mathematical formula `1.0 - distance` was segmented into a different chunk from the provider interface declaration, causing a generic Qdrant configuration chunk to outscore the formula chunk.
3. **Hard-Negative Vulnerability Exacerbation (`hard_negative`):**
   - `exp-049`, `exp-057`, `exp-071`, `exp-050`, `exp-051`, `exp-052`:  
     Smaller chunk embeddings have higher cosine variance and are more easily captured by adversarial distractors sharing 2-3 overlapping keywords. In control, the full document context diluted distractor keywords.

## 10. Raw vs Document-Deduplicated Comparison

Sub-document chunking introduces a structural challenge for top-K evaluation:
- In **Raw Top-5**, if a non-relevant distractor document generates multiple chunks that outscore the ground-truth document, it consumes multiple candidate slots.
- For example, in `exp-064`, 3 chunks from a distractor document occupied ranks 1, 2, and 3, pushing the relevant document out of the top 5 (MRR 0.00).
- In **Document-Deduplicated Top-5**, only the highest-scoring chunk per unique `doc_id` is retained. Sibling chunks are skipped until 5 distinct documents are gathered.
- Deduplication increased MRR from **0.7300 to 0.7471**, raised Hit@3 from **0.8000 to 0.8500**, and elevated Hit@5 from **0.8750 to 0.9125**.

Document-level deduplication is strictly necessary when indexing sub-document chunks in production RAG systems.

---

## 11. Final Decision and Roadmap Recommendations

### Decision: **REJECT**

The sentence-boundary chunking candidate fails both the primary success target (MRR of 0.7471 vs required $\ge 0.8200$) and the multi-concept safety criterion (0.9688 vs 1.0000).

### Engineering Insights for Subsequent Roadmap Milestones:
1. **Sentence Boundary Chunking is Valuable but Insufficient Alone:**  
   Sentence boundary segmentation is empirically proven to solve boundary truncation (`boundary_handling` MRR +0.1667) and exact terminology matches (+0.0625).
2. **Context Window Sizing Trade-Off:**  
   400 characters is too aggressive for dense semantic embeddings on this technical corpus. Small chunks discard the high-level semantic context required for paraphrased queries and multi-concept questions.
3. **Recommended Future Architecture (v1.2 Synthesis):**  
   - **Hierarchical / Parent-Child Chunking:** Embed small sentence-level chunks (300-400 chars) for high-precision retrieval matching, but return the parent document or window (800-1200 chars) to the context and reranker.
   - **Hybrid Retrieval (BM25 + Dense) with Sentence Boundary Chunking:** Combining BM25 sparse matching with sentence-bounded dense chunks will counter the semantic drift observed on hard negatives and paraphrases.

*Integration Status:* No production files were modified. The treatment remains strictly isolated in evaluation artifacts.
