## 1. Executive Summary

In accordance with `docs/Research-Roadmap.md` (Step 9 of the 14-step research lifecycle) and `docs/Product-Roadmap.md`, an isolated, evaluation-only context optimization experiment was executed against the frozen 50-document expanded corpus and 80-case benchmark.

The experiment evaluated whether replacing static Top-5 uncompressed prompt context (averaging ~4,533 characters across 5 chunks) with a dynamic context optimization engine (dynamic prompt budget allocation at 2,500 characters, document deduplication, and extractive keyword-salience compression) improves retrieval efficiency, reduces prompt token consumption, and maintains retrieval quality without regressing safety invariants.

### Key Conclusions

1. **Substantial Prompt Compression Achieved:**  
   Dynamic budget allocation compressed prompt context by **45.96%** (from 4,533 characters down to 2,449 characters), and by **68.11%** in the aggressive mode (1,445 characters), with near-zero latency overhead (P95 of 0.042 ms).
2. **High-Rank Safety Invariants Preserved:**  
   For all high-ranking retrieval hits (ranks 1 to 3), context optimization admitted the relevant documents completely. As a result:
   - `multi_concept` MRR remained strictly **1.0000** (16/16 hits at rank 1).
   - `paraphrase` MRR remained strictly **0.9375** (15/16 hits at rank 1).
   - `cross_document` MRR remained strictly **0.7500**.
3. **Tail Candidate Elimination Inherent in Budget Caps:**  
   Because the candidate pool comes from whole-document chunks (~812 characters each), capping the context budget to 2,500 characters admits at most 2 to 3 whole documents. Consequently, relevant evidence located at rank 4 or 5 is truncated from the prompt context:
   - In `exp-015` (`exact_terminology`), target document sat at rank 5 in control (RR=0.200) $\to$ truncated (RR=0.000).
   - In `exp-050` (`hard_negative`), target document sat at rank 4 in control (RR=0.250) $\to$ truncated (RR=0.000).
   - In `exp-073` (`boundary_handling`), target document sat at rank 5 in control (RR=0.200) $\to$ truncated (RR=0.000).
   - Net effect: Hit@5 dropped from **0.8750 to 0.8375** (-3 cases), and Overall MRR dropped slightly from **0.7623 to 0.7542**.
4. **Target Failure:**  
   Trimming or compressing context cannot improve initial retrieval ranking. Thus, the candidate fails the preregistered primary MRR target of $\ge 0.8200$.

**Decision:** The treatment is **REJECTED** for standalone integration into production retrieval defaults. While it successfully reduces prompt token consumption by ~46%, standalone static character budget allocation penalizes queries where the correct evidence resides at rank 4 or 5.

## 2. Hypothesis & Research Questions

**Hypothesis:**  
Dynamic prompt budget allocation (capping prompt context to 2,500 characters) and extractive salience compression will reduce prompt token consumption by $\ge 30\%$ while preserving overall retrieval MRR ($\ge 0.7623$) and maintaining the `multi_concept` safety invariant ($= 1.0000$) on the frozen 80-case expanded benchmark.

**Research Questions:**
1. Does dynamic context budget allocation degrade recall for queries requiring rank 4–5 evidence?
2. Does extractive sentence salience compression preserve keyword grounding across technical architecture queries?
3. What is the Pareto frontier between prompt token reduction and document retrieval accuracy?

## 4. Implementation Specification

The experiment is implemented in [`evaluation/run_v1_2_context_optimization_experiment.py`](../../evaluation/run_v1_2_context_optimization_experiment.py):
- **Candidate Admittance:** Traverses ranked retrieval candidates (`retrieved_chunk_ids` mapped to unique document IDs via `corpus_v1_2_expanded_ids.json`).
- **Dynamic Character Budget ($B=2,500$ characters):** Each candidate block includes header delimiters (`--- START Source X ---`) and body text.
- **Extractive Salience Compression:** When admitting a candidate that exceeds the remaining budget, sentences matching query keywords are prioritized; boilerplate or preamble sentences are omitted.
- **Deduplication:** Multiple chunks from the same document ID are merged/deduplicated.

## 6. Query Regression & Failure Analysis

## 7. Decision & Production Integration Impact

- **Decision:** **REJECT**.
- **Rationale:**
  1. Failed primary MRR target ($\ge 0.8200$).
  2. While prompt token savings of ~46% are substantial, applying static budget caps to dense whole-document retrieval drops relevant evidence sitting at ranks 4 and 5.
  3. Production RAG pipeline retains static Top-5 uncompressed context assembly via [`ContextBuilder`](../../backend/app/services/rag/context.py).

---

## 8. Lessons Learned & Unified Path Forward

Across all five v1.2 empirical experiments:
1. **Formatting:** Asymmetric task prefixes produced neutral retrieval gain (+0.0000 MRR).
2. **Cross-Encoder Reranking:** Severely violated latency (+1,048 ms) and safety invariants.
3. **Hybrid BM25 + Dense RRF:** Suffered severe vocabulary mismatch on technical corpus (-0.0529 MRR).
4. **Sentence Boundary Chunking:** Fragmented multi-concept semantic narrative (-0.0152 MRR).
5. **Context Optimization:** Successfully compressed prompt tokens by 46%, but inherently cannot improve retrieval MRR and penalizes tail recall (-0.0081 MRR).

**Synthesis:** Standalone pipeline modifications fail because retrieval quality and context optimization are interdependent. The path forward for v1.3+ is **Hierarchical (Parent-Child) Indexing**, where fine sentence chunks are searched for high-precision retrieval and their parent document contexts are dynamically assembled for prompt generation.
