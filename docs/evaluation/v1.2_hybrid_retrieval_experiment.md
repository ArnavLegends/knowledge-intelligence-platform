## 1. Executive Summary

Following the failure analysis in [`docs/evaluation/v1.2_failure_analysis.md`](v1.2_failure_analysis.md) and the rejection of the heavy CPU neural cross-encoder in [`docs/evaluation/v1.2_cross_encoder_experiment.md`](v1.2_cross_encoder_experiment.md), an isolated, evaluation-only hybrid retrieval experiment was designed and evaluated.

The experiment combined KIP's existing dense semantic retrieval (Gemini `gemini-embedding-2` + Qdrant) with an in-memory lexical retriever (deterministic BM25Okapi) fused via standard Reciprocal Rank Fusion (RRF, $k=60$) over the frozen 80-case expanded benchmark and 50-document corpus.

### Key Conclusions

1. **Hypothesis Disproved on Core Retrieval Quality:**  
   The primary hypothesis—that combining dense semantic vectors with BM25 via RRF would improve overall MRR to $\ge 0.8500$ and resolve hard-negative confusion—was **disproved**. Overall MRR dropped from **0.7623 to 0.7094** ($-0.0529$).
2. **Selective Strength on Exact Terminology:**  
   As hypothesized, BM25 excels at exact keyword matching. In the `exact_terminology` category:
   - Hit Rate @ 1 improved from **0.6875 $\rightarrow$ 0.7500** ($+0.0625$).
   - Category MRR improved from **0.7937 $\rightarrow$ 0.8333** ($+0.0396$).
   - `cross_document` MRR also rose from **0.7500 $\rightarrow$ 0.8125** ($+0.0625$).
3. **Severe Regressions in Paraphrase and Hard Negatives:**  
   - **Paraphrase Collapse:** MRR dropped dramatically from **0.9375 to 0.6979** ($-0.2396$). Because paraphrase queries use conceptual synonyms that lack lexical overlap with the target documents, BM25 ranked irrelevant documents with incidental token matches at top positions. When fused via RRF, these false lexical signals diluted dense semantic top ranks.
   - **Hard Negative Susceptibility:** Hard negative MRR regressed from **0.4427 to 0.3906** ($-0.0521$). Semantic distractors in the corpus (e.g., `distractor_hybrid_search_proposals.txt`, `distractor_redis_cache_layer.txt`) contain high densities of technical keywords mentioned in adversarial queries. BM25 promoted these distractors to rank 1, degrading ranking quality.
4. **Negligible Latency Overhead (Guardrail Passed):**  
   Unlike the CPU cross-encoder (which introduced $+791$ ms overhead and breached the latency guardrail at 1,691.5 ms), BM25 sparse retrieval required an average of **0.27 ms** and RRF fusion took **0.11 ms**. Total end-to-end P95 latency was **618.9 ms**, comfortably within the 300 ms guardrail.

**Decision:** The hybrid retrieval treatment (Dense + BM25 with uniform RRF $k=60$) is **REJECTED** as a production default.

## 2. Experimental Hypothesis and Design

### Hypothesis
Combining dense semantic retrieval with BM25-style lexical retrieval using Reciprocal Rank Fusion (RRF) will improve exact-terminology retrieval, hard-negative discrimination, and ranking quality while preserving paraphrase and multi-concept performance, with less latency overhead than the rejected CPU cross-encoder.

- **Benchmark:** 80 cases (`benchmarks/kip_v1_2_expanded_benchmark.json`), verified 80 unique cases.

## 3. Treatment Pipeline Specifications

### Channel A: Dense Semantic Retrieval
- **Embedding Model:** Google Gemini `gemini-embedding-2` (768 dimensions)
- **Vector Database:** Qdrant (in-memory, Cosine distance)
- **Candidate Top-K:** 20 passages

### Channel B: Sparse Lexical Retrieval (BM25Okapi)
- **Implementation:** [`evaluation/bm25.py`](../../evaluation/bm25.py), isolated deterministic Python index over the exact 50 corpus document chunks.
- **Scoring Formulation:** Standard Robertson-Spärck Jones BM25Okapi:
  $$\text{Score}(d, Q) = \sum_{t \in Q} \text{IDF}(t) \cdot \frac{f(t, d) \cdot (k_1 + 1)}{f(t, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}}\right)}$$
- **Parameters:** $k_1 = 1.5$, $b = 0.75$.
- **IDF with Lucene Smoothing:**
  $$\text{IDF}(t) = \ln \left( 1.0 + \frac{N - n(t) + 0.5}{n(t) + 0.5} \right)$$
- **Text Normalization:** Lowercasing, regex tokenization `\b[a-zA-Z0-9_\-]+\b|\b\w+\b` preserving alphanumeric words and hyphenated domain terms (`x-kip-workspace-id`).
- **Candidate Top-K:** 20 passages

### Fusion Stage: Reciprocal Rank Fusion (RRF)
- **Implementation:** [`evaluation/fusion.py`](../../evaluation/fusion.py)
- **Formulation:**
  $$\text{RRF}(d) = \sum_{r \in \{\text{dense}, \text{sparse}\}} \frac{1}{k + \text{rank}_r(d)}$$
- **Smoothing Constant:** $k = 60$ (fixed standard literature constant).
- **Deduplication:** Merged by stable chunk ID.
- **Tie-Breaking:** Deterministic tie-breaking on RRF score $\rightarrow$ lowest single-channel rank $\rightarrow$ chunk ID string.
- **Returned Top-K:** Final top 5 results.

## 6. Failure Case Analysis

A total of **10 cases improved**, while **18 cases regressed** and **52 cases remained unchanged**.

### Why Exact Terminology and Cross-Document Improved
1. **`exp-006`** (*"How many dimensions does the production Gemini embedding model generate in KIP?"*):  
   - Control: Rank 2 (MRR 0.500)
   - Treatment: **Rank 1 (MRR 1.000)**  
   - Reason: The query contains `"768"` / `"dimensions"`. BM25 assigned high weight to `kip_embedding_service.txt`, promoting it over partial vector matches.
2. **`exp-069`** (*"How do Qdrant Cloud and embedded Chroma vector store implementations enforce workspace tenant filtering?"*):  
   - Control: Rank 2 (MRR 0.500)
   - Treatment: **Rank 1 (MRR 1.000)**  
   - Reason: Exact matching on `"tenant filtering"` and `"payload"` boosted the relevant architecture document directly to rank 1.
3. **`exp-070`** (*"What language model providers can power answer generation and what models do they target?"*):  
   - Control: Miss (MRR 0.000)
   - Treatment: **Rank 1 (MRR 1.000)**  
   - Reason: The document had fallen out of dense top-5 due to generic embedding similarity with other gateway files. BM25 retrieved it at rank 1, pulling it directly into fused rank 1.

### Why Paraphrase Queries Collapsed
In natural language queries that do not mirror the corpus phrasing, lexical matching acts as destructive noise:
1. **`exp-018`** (*"How does the platform ensure that repeatedly re-indexing a text file never duplicates data?"*):  
   - Target Document: `kip_ingestion_and_chunking.txt` (describes SHA-256 deduplication).
   - Control Dense: **Rank 1 (MRR 1.000)** (Gemini embeddings matched the semantic concept of idempotent indexing).
   - Treatment Hybrid: **Miss (MRR 0.000)**.
   - Diagnostic: BM25 assigned score 0.0 to the target document because words like `"repeatedly re-indexing"` did not appear verbatim in `kip_ingestion_and_chunking.txt`. Instead, BM25 retrieved distractors with terms like `"text file"`. The target chunk was demoted below top 5.
2. **`exp-022`** (*"What prevents one enterprise tenant from reading another organization's confidential embeddings?"*):  
   - Target Document: `kip_multitenancy_architecture.txt` (describes workspace UUID filtering).
   - Control Dense: **Rank 1 (MRR 1.000)**.
   - Treatment Hybrid: **Miss (MRR 0.000)**.
   - Diagnostic: The target text uses `"workspace_id"`, `"tenant"`, and `"isolation"`. The query uses `"enterprise tenant"`, `"organization"`, and `"confidential embeddings"`. BM25 had zero hits on the target document, pushing it out of the fused top 5.

### Why Hard Negatives Regressed
Adversarial queries inherently contain the keywords of the concept they are asking about:
- **`exp-051`** (*"Does KIP currently utilize sparse lexical search like BM25 or SPLADE in its retrieval pipeline?"*):  
  - Target Document: `kip_retrieval_and_rag.txt` (affirms dense vector search only).
  - Distractor Document: `distractor_hybrid_search_proposals.txt` (heavily discusses BM25, SPLADE, and FastEmbed).
  - Control Dense: Rank 2 (MRR 0.500).
  - Treatment Hybrid: **Rank 3 (MRR 0.333)**.
  - Diagnostic: BM25 ranked `distractor_hybrid_search_proposals.txt` at **Rank 1** with score 6.18 because the query terms `"sparse"`, `"lexical"`, `"BM25"`, and `"SPLADE"` all match the distractor passage with high term frequency.

## 9. Final Decision & Research Direction

### Decision: REJECT
Hybrid retrieval via uniform Reciprocal Rank Fusion ($k=60$) is **REJECTED** for KIP retrieval.

While it is exceptionally fast and improves exact terminology matching (+0.0396 MRR, +0.0625 Hit@1), it causes a severe $-0.2396$ drop in paraphrase queries and exacerbates false positives on keyword-heavy hard negatives.

### Architectural Takeaway
In technical RAG domains with adversarial hard negatives and conversational/paraphrased user queries, unweighted rank fusion between lexical and dense retrieval is detrimental:
1. When a query is paraphrased, BM25 provides negative/random signal that corrupts dense rankings.
2. When a query contains negative constraints or asks about unadopted features, BM25 preferentially selects distractors with high keyword density.

### Recommended Next Research Candidate
- **Selective / Routing-Based Fusion or Query Classifier:**  
  Rather than applying BM25 blindly to every query, invoke sparse retrieval only when specific technical patterns (such as exact acronyms, error codes, HTTP header patterns, or function names like `X-KIP-Workspace-ID`) are detected, or use score-thresholded fusion where BM25 only intervenes if its top score exhibits high statistical confidence above background corpus noise.
