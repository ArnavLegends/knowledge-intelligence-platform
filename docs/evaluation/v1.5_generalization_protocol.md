# v1.5 Evaluation Protocol — Generalization to Independent Corpora

**Status:** DRAFT — Frozen for review. No experimental results are included.
**Version:** v1.5-proto-2026-10-23
**Authors:** KIP Research Team
**Depends on:** v1.4 deliverables (workspace inventory, deletion endpoint, parser error feedback)

---

## 1. Research Questions

This protocol addresses three primary questions that v1.4 data cannot answer:

| ID | Question |
|----|----------|
| RQ-1 | Does the retrieval quality observed in the v1.4 expanded benchmark (dense baseline MRR 0.7623) generalise to an independent corpus outside the KIP technical documentation domain? |
| RQ-2 | Do the v1.4 treatments that improved retrieval (sentence chunking, hybrid retrieval) maintain their relative advantage on a secondary corpus, or was the improvement domain-specific? |
| RQ-3 | Does the system produce unsupported or fabricated claims (hallucination) at measurable rates, and can the system correctly abstain when the answer is not present in the indexed corpus? |

---

## 2. Falsifiable Hypotheses

The following hypotheses are stated before any v1.5 data is collected. Results will be reported regardless of whether the hypotheses are confirmed or refuted.

| ID | Hypothesis | Falsification Criterion |
|----|------------|------------------------|
| H-1 | Dense baseline MRR on the secondary corpus will fall within ±0.10 of the v1.4 expanded baseline (0.7623). | MRR differs by more than 0.10 in either direction. |
| H-2 | The sentence-chunking treatment will maintain positive delta over whole-document chunking on the secondary corpus. | Sentence chunking ≤ whole-document chunking MRR on secondary corpus. |
| H-3 | The system will abstain (produce a refusal or "not found" response) for ≥ 80% of unanswerable questions. | Abstention rate < 80% on the unanswerable query set. |
| H-4 | Citation fidelity (answer claim traceable to a retrieved passage) will be ≥ 75% of evaluated answers. | Citation fidelity < 75%. |

## 3. Secondary Corpus Selection

### 3.1 Design Constraints

- **Independence:** Corpus must not overlap with any document in the v1.4 benchmark collection.
- **Domain:** Non-KIP technical documentation. Candidates include: public technical standards (RFCs, W3C specs), open-licensed academic survey papers, or publicly available government technical reports.
- **Size:** Approximately 30 documents, targeting 150–250 total chunks under the default chunking configuration.
- **Language:** English only for v1.5.
- **License:** Documents must be explicitly public domain or openly licensed (CC-BY, CC0, or equivalent) to permit redistribution and annotation.

### 3.2 Selection Procedure

1. Three candidate corpora will be proposed and reviewed against the independence constraint.
2. Final corpus selection will be ratified by at least two reviewers before any evaluation begins.
3. The selected document list (filenames, sources, SHA-256 hashes) will be committed to `evaluation/v1.5/corpus_manifest.json` before any queries are authored.

### 3.3 Corpus Manifest Schema

```json
{
  "corpus_id": "v1.5-secondary",
  "created_at": "<ISO-8601>",
  "documents": [
    {
      "filename": "example_rfc.pdf",
      "source_url": "https://...",
      "sha256": "...",
      "license": "public-domain",
      "word_count": 12400,
      "domain": "networking-standards"
    }
  ]
}
```

## 4. Query Set Design

### 4.1 Query Categories

| Category | Count | Description |
|----------|-------|-------------|
| Terminology | 10 | Single-concept lookups for domain terms defined in the corpus |
| Paraphrase | 10 | Same factual need expressed with different vocabulary than the source text |
| Multi-concept | 10 | Queries requiring synthesis of information from 2+ passages |
| Hard-negative | 10 | Queries topically adjacent to corpus content but whose precise answer is absent |
| Cross-document | 10 | Queries whose answer requires information from ≥ 2 distinct documents |
| Unanswerable / Abstention | 10 | Queries with no supporting evidence in the corpus (out-of-scope facts) |

**Total: 60 queries**

### 4.2 Ground Truth Labeling

- Each query is labeled with a set of **relevant chunk IDs** (retrieved from the corpus) and a **reference answer** (or "unanswerable" for the abstention set).
- Labeling is performed by two independent annotators.
- Disagreements are resolved by a third reviewer. Final labels are locked before any retrieval system is invoked.
- Inter-annotator agreement (Cohen's κ) must be ≥ 0.70 before the label set is accepted.

### 4.3 Label Format

```json
{
  "query_id": "v1.5-q-001",
  "query_text": "...",
  "category": "terminology",
  "relevant_chunk_ids": ["chunk-abc", "chunk-def"],
  "reference_answer": "...",
  "is_answerable": true,
  "annotator_agreement_kappa": 0.82
}
```

## 5. Evaluation Tracks

This section describes planned evaluation tracks. **Track D (hierarchical retrieval) is treated strictly as an unverified architectural hypothesis.** No hierarchical retrieval component exists in production. It may only appear in v1.5 if a tracked, independently validated implementation is available.

### Track A — Control Baseline (Dense, Whole-Document Chunking)

- Configuration: same as v1.4 expanded baseline (dense embeddings, fixed-size whole-document chunking, no reranking).
- Purpose: direct comparability anchor between v1.4 and v1.5.
- Configuration hash: computed and stored before evaluation begins.

### Track B — Best-Performing v1.4 Treatment

- Configuration: the single treatment from the v1.4 expanded benchmark with the highest validated MRR (to be confirmed from v1.4 frozen results).
- Purpose: test whether the v1.4 improvement transfers to the secondary corpus.

### Track C — Abstention and Citation Evaluation

- Applied to Track A responses only.
- LLM-generated answers scored against ground truth by human raters for:
  - Citation fidelity: is each claim in the answer traceable to a retrieved passage?
  - Unsupported-claim rate: fraction of answer claims with no retrievable support.
  - Abstention correctness: did the system correctly decline to answer unanswerable queries?

### Track D — Hierarchical Retrieval (Hypothesis Only, v1.5+ Gate)

- **Blocked pending architectural implementation.** No code or benchmark infrastructure exists.
- Inclusion in v1.5 final evaluation is conditional on Track D passing an internal integration gate (working end-to-end implementation with unit test coverage ≥ 85%).
- If the gate is not passed, Track D is deferred to v1.6.

## 6. Retrieval Metrics

The following metrics are computed for Tracks A and B:

| Metric | Definition | Implementation |
|--------|-----------|----------------|
| MRR@K | Mean Reciprocal Rank at K, K ∈ {5, 10} | `evaluation/validate_benchmark_metrics.py` conventions |
| Hit@1 | Fraction of queries where rank-1 result is relevant | Binary per query |
| Hit@3 | Fraction of queries with ≥ 1 relevant result in top 3 | Binary per query |
| Hit@5 | Fraction of queries with ≥ 1 relevant result in top 5 | Binary per query |
| Precision@K | Fraction of top-K results that are relevant, K=5 | Averaged over queries |

---

## 7. Answer-Level Evaluation

Applied exclusively to Track C:

| Metric | Definition | Method |
|--------|-----------|--------|
| Citation Fidelity (CF) | Proportion of answer claims supported by ≥ 1 retrieved chunk | Human rater scoring (1 rater per answer, 10% double-rated) |
| Unsupported Claim Rate (UCR) | Proportion of answer claims not traceable to any retrieved passage | Complement of CF for rated claims |
| Abstention Rate | Fraction of unanswerable queries for which the system does not assert a factual answer | Human binary judgment |
| Abstention Precision | Fraction of abstentions that are correct (query truly unanswerable) | Check against ground truth |

**Scoring rubric for citation fidelity:**

- **Supported (1):** The claim appears verbatim or is a faithful paraphrase of a retrieved chunk.
- **Partially supported (0.5):** The claim partially aligns but omits or adds details.
- **Unsupported (0):** No retrieved chunk contains the information asserted.

## 8. Latency Scopes

Latency must be measured and reported separately for each stage. All measurements use P50 and P95 over a minimum of 30 queries under controlled conditions (local deployment, no network I/O to cloud providers):

| Scope Label | Description |
|-------------|-------------|
| `retrieval_p50` / `retrieval_p95` | Time from query embedding completion to ranked results returned |
| `embedding_p50` / `embedding_p95` | Time to embed a single query |
| `reranker_p50` / `reranker_p95` | Time for cross-encoder reranking stage (if applicable) |
| `llm_p50` / `llm_p95` | Time for LLM answer generation (excluded from retrieval scope) |
| `end_to_end_p50` / `end_to_end_p95` | Total query-to-answer latency including all stages |

Latency results are informational for v1.5. No latency-based elimination criteria are applied unless a treatment exceeds 2× the baseline end-to-end P95.

---

## 9. Configuration Hashes

Before each track evaluation begins:

1. A JSON snapshot of the active configuration (chunker type, chunk size, overlap, embedding model, top-K, threshold, reranking flag) is written to `evaluation/v1.5/configs/<track_id>_config.json`.
2. Its SHA-256 hash is recorded in `evaluation/v1.5/evaluation_run_log.json`.
3. Configuration must not change after hash is recorded.

This ensures that results are reproducible and attributable to an exact system configuration.

## 10. Threats to Validity

| Threat | Mitigation |
|--------|-----------|
| Query-corpus semantic leakage (queries crafted after corpus was read) | Queries are authored by a different person than the one who selected the corpus. |
| Annotator familiarity bias in citation scoring | 10% double-rating with Cohen's κ cross-check. |
| Selection bias in secondary corpus (easy domain) | Corpus candidates are reviewed for difficulty distribution before ratification. |
| Small query set (N=60) limiting statistical power | Confidence intervals (95%, Wilson) reported alongside all point estimates; no significant test is applied without appropriate power analysis. |
| System-state differences between v1.4 and v1.5 runs | v1.4 control baseline configuration is frozen and version-locked. |
| Hierarchical retrieval hypothesis contaminating baseline | Track D is completely independent; results are never mixed with Tracks A/B/C. |

## 11. Decision Gates

Results from v1.5 govern the following decisions:

| Gate | Condition | Action |
|------|-----------|--------|
| G-1: Generalization confirmed | H-1 supported (MRR within ±0.10 of baseline) | Proceed to v1.6 production readiness evaluation. |
| G-1: Generalization failed | H-1 falsified | Perform root cause analysis; scope a targeted remediation track before v1.6. |
| G-2: Treatment delta sustained | H-2 supported | Maintain best treatment as candidate for production default. |
| G-2: Treatment delta not sustained | H-2 falsified | Revert to dense whole-document baseline as production default; investigate interaction effects. |
| G-3: Abstention acceptable | H-3 supported (≥ 80%) | No abstention intervention required for v1.6. |
| G-3: Abstention insufficient | H-3 falsified | Design abstention improvement track for v1.6. |
| G-4: Citation fidelity acceptable | H-4 supported (≥ 75%) | No citation-quality intervention required for v1.6. |
| G-4: Citation fidelity insufficient | H-4 falsified | Investigate prompt or retrieval quality as cause; scope improvement track. |
| G-5: Track D gate | Integration gate passed (implementation exists, tests pass) | Track D included in v1.5 evaluation. |
| G-5: Track D gate | Integration gate not passed | Track D deferred to v1.6. |

## 12. Relationship to v1.4 Benchmark

| Aspect | v1.4 Expanded Benchmark | v1.5 Secondary Corpus |
|--------|------------------------|----------------------|
| Corpus | 50 KIP technical documents | ~30 independent documents (non-KIP domain) |
| Query count | 80 queries | 60 queries |
| Evaluation populations | Pilot (18 docs, 25 queries, MRR 0.9133) + Expanded (50 docs, 80 queries, baseline MRR 0.7623) — kept strictly separate | Single population; no pilot/expanded split |
| Purpose | Establish and validate retrieval quality on KIP domain | Test generalization beyond KIP domain |
| Ground truth method | Manual annotation by single annotator | Double-annotated with κ cross-check |
| Citation / abstention scoring | Not evaluated | Evaluated under Track C |

## 13. Reporting Requirements

The v1.5 evaluation report must include:

1. Corpus manifest (document list with hashes).
2. Query set with category breakdown and inter-annotator κ.
3. Per-track retrieval metrics table (MRR@5, MRR@10, Hit@1, Hit@3, Hit@5, Precision@5) with 95% confidence intervals.
4. Per-category MRR breakdown.
5. Track C answer-level metrics (CF, UCR, abstention rate, abstention precision).
6. Latency measurements per scope and track.
7. Configuration hashes and JSON snapshots for all tracks.
8. Hypothesis confirmation/falsification table.
9. Decision gate outcomes.
10. Open questions and deferred items for v1.6.

**Fabricated results are prohibited.** If any evaluation run fails to complete, it must be reported as incomplete with the reason. Partial results must be clearly labeled as partial.

---

## 14. Non-Goals for v1.5

The following are explicitly out of scope:

- Multilingual evaluation.
- Evaluation against live external APIs (Gemini, Qdrant Cloud) — free-tier and quota constraints apply.
- Any production deployment changes.
- Any changes to v1.4 frozen benchmark data or results.
- Hierarchical retrieval (unless Track D integration gate is passed).
- User study or A/B testing.
